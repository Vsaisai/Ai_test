# Каталог F95Zone

F95Zone подключён как **источник метаданных**. Приложение собирает сведения об играх и ведёт пользователя
на исходную страницу и на официальные страницы разработчика. Файлы игр, ссылки на скачивание, зеркала и
репаки не читаются, не хранятся и не показываются.

Чтобы включить каталог: «Настройки → Что показывать → Показывать всё», затем «Дополнительно → F95Zone».

## Откуда берутся данные

| Что | Адрес | Когда |
|---|---|---|
| Лента релизов (новые и обновлённые сверху) | `/sam/latest_alpha/latest_data.php?cmd=list&cat=games&page=N&sort=date&rows=90` — публичная JSON-лента страницы «Latest updates» | «Обновить», «Загрузить всю ленту» |
| Названия тегов и префиксов | `/sam/latest_alpha/` (объект `latestUpdates`); если нужен вход — встроенный снимок 154 тегов | перед чтением ленты |
| Список всех тем форума Games | `/forums/games.2/page-N` — собственный список сайта | «Сверить с форумом» |
| Описание, теги, официальные ссылки | `/threads/<id>/` — публичная страница игры | при открытии игры; при сверке — для тем, которых не было в ленте |

Основания проверены 9 ноября 2026.

- **robots.txt.** Для `User-agent: *` эти пути разрешены. Запрещены только адреса форума с параметрами
  (`/forums/*?`), поиск, вложения и `/goto/`, и приложение их не использует. Указано
  `Content-Signal: search=yes, ai-train=no`.
- **Правила сайта** (`/help/terms/`) не запрещают автоматическое чтение публичных страниц.
- **Официального API нет.** Лента — внутренний интерфейс страницы сайта, она не документирована. Для
  коммерческого использования стоит получить письменное разрешение владельцев (`/pages/contact/`).

## Полнота каталога

Лента сама сообщает число страниц. «Загрузить всю ленту» читает их все; лимит 5000 страниц нужен только для
безопасности. **Что в ленте есть все игры форума, не доказано.** Поэтому полнота подтверждается отдельно:

1. **«Загрузить всю ленту».** Читает все страницы. Прерванная загрузка (капча, обрыв связи) в следующий раз
   продолжается с той же страницы. В конце первые страницы перечитываются, пока две подряд не принесут
   ничего нового: так ловятся релизы, которые поднялись наверх, пока шло чтение. Страница, которую не
   удалось прочитать даже после повтора, записывается в отчёт, и проход не считается завершённым.
2. **«Сверить с форумом».** Читает все страницы списка тем форума Games (`/forums/games.2/page-N`):
   - темы, которых нет в каталоге, добавляются (`found_via = forum`);
   - их страницы читаются, чтобы узнать теги (до 300 за запуск, по 2 с);
   - закреплённые служебные темы (правила, объявления) не считаются.
3. Настройки пишут **«Полнота подтверждена»** только когда сверка прочитала все страницы без остановки и у
   всех найденных тем прочитаны страницы. В остальных случаях — «Полнота не подтверждена» с причиной.

Подтвердить полноту на настоящем сайте можно только живой проверкой (см. ниже). У разработчика доступа к
сайту нет: robots.txt запрещает агенты Claude (`Claude-User`, `ClaudeBot`). Всё проверено на локальном
тестовом сервере с той же структурой ответов.

## Обновление и почему оно не пропускает старые релизы

- «Обновить» читает ленту с первой страницы и останавливается после **двух подряд** страниц без новых и
  изменённых релизов.
- Такой режим разрешён **только после завершённого прохода по всей ленте**. До этого «Обновить» само читает
  всю ленту. Поэтому на неполном каталоге старые релизы не теряются.
- После полного прохода любой новый или обновлённый релиз поднимается в начало ленты (она отсортирована по
  дате обновления), и обновление его увидит.
- Лента не покажет наверху тему, которая появилась в форуме со старой датой (перенесена из другого раздела
  или восстановлена модераторами). Такие темы находит только «Сверить с форумом». Её стоит запускать
  периодически, например раз в неделю.

## Ограничения контента

- **Игры с тегами `loli` и `shota`** (сексуализация несовершеннолетних) **не показываются нигде**: ни в
  списке, ни в поиске, ни на страницах новелл, ни на полке главной, ни через API.
- Такие записи **сохраняются**, чтобы ничего не терялось незаметно: номер темы, название, разработчик, теги,
  версия, дата. Причина пишется в `hidden_reason`. Обложка, описание и ссылки для них не сохраняются.
- Они **учитываются** в отчётах: «Скрыто правилами приложения: N (loli: …, shota: …)».
- Скрытие **необратимо**: если позже тег пропадёт из ленты, запись всё равно останется скрытой.
- Тема, найденная только в списке форума (без тегов), **не показывается**, пока не прочитана её страница
  и не проверены теги (`needs_check`).
- Другие категории (жанры, движки, статусы) ничего не скрывают, их можно только отфильтровать в поиске.

## Описание

- Сохраняется **всё публичное описание** игры (раздел Overview первого сообщения) с ограничением 20 000
  знаков на случай ошибочной вёрстки.
- В интерфейсе длинное описание свёрнуто до 1200 знаков, по кнопке раскрывается полностью. Рядом всегда
  указан источник и стоит ссылка на страницу.
- Описание читается **только когда пользователь открывает игру**, как это сделал бы браузер. Массовая
  загрузка описаний не выполняется.
- robots.txt разрешает поисковое использование «со ссылками и короткими выдержками». Полный текст на
  экране пользователя — это показ страницы по его запросу. Права на текст принадлежат разработчикам игр.

## Совпадения с VNDB

Автоматически, сильнейший признак побеждает:

1. та же страница игры (Steam app, itch.io-игра, DLsite) у релиза ровно одной новеллы VNDB;
2. название + страница разработчика (Patreon, SubscribeStar), указанная у релизов этой новеллы;
3. название + имя разработчика;
4. название, которое есть ровно у одной новеллы 18+. Это слабое совпадение, его стоит проверить.

Ручная проверка:

- фильтр «Совпадения с VNDB» в списке игр: «Найдены только по названию — проверить», «Исправлены вручную»,
  «Нет в VNDB», «Есть в VNDB»;
- на странице игры: «Верно», «Неверно — отвязать», «Подтвердить: нет в VNDB», «Указать другую новеллу»
  (номер `v1234` или ссылка vndb.org), «Вернуть автоподбор»;
- на странице новеллы VNDB: «не та игра»;
- ручное решение (`match_manual`) автоматический подбор больше не меняет.

## Отчёт об импорте

После каждого запуска сохраняется и показывается в настройках:

| Показатель | Что считается |
|---|---|
| Обнаружено релизов | разных тем, встреченных в ленте за этот запуск |
| Новых записей | тем, которых раньше не было в каталоге |
| Обновлённых записей | изменилась версия, дата, название или теги |
| Пропущено | без изменений + скрыто правилами (оба числа отдельно) |
| Ошибок | нечитаемые записи ленты + непрочитанные страницы (их номера) |
| Дубликатов | лишние записи с тем же названием и разработчиком; отдельно — повторы, когда лента сдвинулась во время чтения |
| Объединено с VNDB | записей, связанных с новеллой VNDB |

Сверка с форумом пишет свой отчёт: тем в форуме, уже были в каталоге, не было в ленте (добавлены),
проверено страниц, скрыто правилами, ошибок, прочитаны ли все страницы.

## Живая проверка

Безопасный тест на настоящем сайте: около 7 запросов с паузой 2 с, без входа и без обхода защиты.

- **Из приложения:** «Настройки → Дополнительно → F95Zone → Проверить подключение».
- **Из консоли на ПК:**

  ```
  vndb-web f95-check --games 3
  ```

Что проверяется:

1. словарь тегов: с сайта или встроенный снимок;
2. первая страница ленты: игры, теги, статусы, нечитаемые записи;
3. последняя страница ленты: **точное число релизов в ленте**;
4. первая и последняя страница списка тем форума Games: **число тем в форуме**;
5. сравнение: если в форуме тем больше, лента неполная, и нужна сверка;
6. три страницы игр: название, теги, длина описания, обложка, официальные ссылки, сохранение.

Если сайт ограничит доступ, проверка остановится и скажет, на каком шаге.

## Правила доступа

- Не чаще одного запроса в 2 с на всё приложение; User-Agent называет приложение; без cookies и входа.
- Ответ 429/403, проверка Cloudflare или DDoS-Guard, капча или страница входа останавливают работу и
  показывают причину. Обходов нет. Прочитанное сохраняется.

## Устройство

- `crates/core/src/external/mod.rs` — интерфейс `Provider`: `prepare`, `list`, `details`, `index_page`.
  Там же сценарии `refresh` (полный проход, продолжение, обновление) и `audit` (сверка), отчёты, правила
  контента.
- `crates/core/src/external/f95zone.rs` — `F95Zone: Provider`: запросы, проверки ответов, разбор ленты,
  списка тем и страницы игры, живая проверка.
- `crates/core/src/external/store.rs` — `external.sqlite`: записи, видимость (`blocked`, `needs_check`),
  ручные совпадения, поиск, статистика.
- `crates/core/src/external/matching.rs` — правила совпадений с VNDB.
- `crates/server/src/external_api.rs` — эндпоинты:
  - `/api/ext/status`, `/api/ext/refresh`, `/api/ext/audit`, `/api/ext/check`;
  - `/api/ext/search`, `/api/ext/tags`;
  - `/api/ext/game/:source/:id`, `/api/ext/game/:source/:id/match`.
- `web/js/external.js` — интерфейс.

Для разработки переменная `VNSHELF_F95_BASE=http://127.0.0.1:<порт>` направляет запросы на локальный
тестовый сервер. Принимаются только адреса `127.0.0.1` и `localhost`.

## Что ещё не подтверждено

- Разбор списка тем форума и страниц игр написан по устройству XenForo 2 и проверен на тестовых
  страницах. На настоящей вёрстке его подтвердит только живая проверка.
- Совпадает ли размер ленты с числом тем форума, покажет живая проверка (шаги 3–5).
- Если словарь тегов на `/sam/latest_alpha/` требует входа, новые теги, которых нет в снимке, появятся
  только после чтения страницы игры.
