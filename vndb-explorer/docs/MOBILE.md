# Мобильное приложение

## Готовое Android-приложение (ветка `mobile`)

APK публикуется в [GitHub Releases](https://github.com/Vsaisai/Ai_test/releases) (теги `mobile-v*`).
Приложение полностью автономное: внутри APK работает тот же Rust-сервер, что и на ПК
(`crates/mobile` → `libvnshelf.so`), а интерфейс показывается во WebView. Компьютер не нужен.

* Первый запуск: «Скачать базу VNDB» (~190 МБ) — импорт потоковый, ~15 МБ ОЗУ, 1–3 минуты.
* При каждом запуске (не чаще раза в 6 часов) приложение сверяется с VNDB:
  мелкие расхождения (новые новеллы и релизы) подтягиваются автоматически через API,
  большие (больше 1 500 новелл / 6 000 релизов / 90 дней с полной загрузки) — по выбору
  в настройках: спросить или обновить полностью самостоятельно.
* Раз в сутки проверяется, не вышла ли новая версия APK (если репозиторий публичный; для
  закрытого — кнопка ведёт на страницу релизов).
* Данные лежат во внутренней памяти приложения и переживают обновление APK.

### Сборка

```bash
ANDROID_HOME=~/Android/Sdk ANDROID_NDK_HOME=~/Android/Sdk/ndk/27.2.12479018 ./mobile/build-apk.sh
```

Нужны JDK 17+, Android SDK (platform 35, build-tools 35), NDK, `cargo install cargo-ndk` и
`rustup target add aarch64-linux-android armv7-linux-androideabi x86_64-linux-android`.
Результат — `target/apk/VNShelf-<версия>.apk`.

### Выпуск новой версии

Поменяйте номер в `mobile/VERSION` и запушьте ветку `mobile`. Workflow `.github/workflows/android.yml`
соберёт APK и, если релиза `mobile-v<версия>` ещё нет, создаст его (вместе с тегом). Пуш тега
`mobile-v*` тоже запускает сборку. По умолчанию APK подписывается
отладочным ключом из репозитория (`mobile/android/app/debug.keystore`), чтобы обновления ставились
поверх. Для настоящей подписи добавьте секреты `ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`,
`ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD` (после смены ключа приложение придётся один раз
переустановить).

## Другие варианты

Проект с самого начала разделён так, чтобы веб-интерфейс можно было превратить в приложение
для телефона без переписывания логики.

| Слой | Где | Зависит от |
|---|---|---|
| Логика (импорт, поиск, полки, «где взять») | `crates/core` | только Rust + SQLite |
| Транспорт | `crates/server` (HTTP) | `core` |
| Интерфейс | `web/` (HTML/CSS/ES-модули, без сборки) | только `web/js/api.js` |

### Вариант 0 — PWA (готово сейчас)

1. На ПК: `vndb-web serve --addr 0.0.0.0:8080`.
2. На телефоне: открыть `http://IP-компьютера:8080` → меню браузера → «Установить приложение» /
   «На экран Домой».

Работает как приложение (без адресной строки), интерфейс и просмотренные обложки кешируются
service worker'ом. Нужен запущенный ПК в той же сети.

### Вариант 1 — обёртка (Capacitor), сервер на ПК

Самый быстрый путь к APK/IPA:

1. `npm create @capacitor/app`, в `webDir` указать папку `web/`.
2. В приложении открыть «Настройки → Сервер» и указать `http://IP-компьютера:8080`
   (это `apiBase` в `web/js/store.js`; CORS на сервере уже разрешён).
3. `npx cap add android` / `npx cap add ios`, собрать.

Минус: нужен сервер на ПК.

### Вариант 2 — полностью автономное приложение (Tauri 2)

Tauri 2 собирает Android/iOS и позволяет вызывать Rust-код напрямую, так что `vndb-core`
работает прямо на телефоне, без ПК:

1. `cargo tauri init` (или `npm create tauri-app`), `frontendDist` → `../web`.
2. В `src-tauri/Cargo.toml` добавить `vndb-core = { path = "../crates/core" }`.
3. Объявить команды-обёртки — по одной на эндпоинт, с теми же типами:

   ```rust
   #[tauri::command]
   fn search(state: tauri::State<AppState>, req: vndb_core::SearchRequest) -> Result<vndb_core::SearchResponse, String> {
       vndb_core::search(&state.catalog, &req).map_err(|e| e.to_string())
   }
   ```

4. В `web/js/api.js` заменить `call(method, path, body)` на `window.__TAURI__.core.invoke(...)`
   (весь остальной интерфейс трогать не нужно — он ходит только через `api`).
5. Импорт базы: `vndb_core::import::import(Source::Url(DUMP_URL), path, &progress)` в фоне
   (≈190 МБ загрузки, ≈150 МБ на диске; на телефоне занимает около минуты).
6. Обложки: либо грузить напрямую с `https://t.vndb.org/…`, либо добавить команду-кеш как
   `/img/*` в сервере.

Что учесть на телефоне:

* Память: каталог в памяти занимает ~150 МБ — нормально для современных телефонов. Если нужно
  меньше, `Catalog` можно загружать без `search_text` и искать по названиям через SQLite FTS.
* Импорт потоковый и использует ~15 МБ ОЗУ, так что полную загрузку можно делать прямо на телефоне.

### Вариант 3 — нативный UI (Kotlin/Swift/Flutter)

`vndb-core` можно собрать как библиотеку (`crate-type = ["cdylib", "staticlib"]`) и подключить через
UniFFI или `flutter_rust_bridge`. Модели (`SearchRequest`, `Card`, `Detail`) уже сериализуются в JSON,
поэтому самый простой мост — функции «JSON на входе, JSON на выходе».

## Обновления из закрытого репозитория

Пока репозиторий приватный, GitHub не отдаёт список релизов без авторизации. Приложение проверяет версию и
скачивает APK через свой локальный сервер, который добавляет токен (в WebView и JavaScript токен не попадает).

1. GitHub → Settings → Developer settings → Fine-grained personal access tokens → Generate new token.
   Repository access: только `Vsaisai/Ai_test`; Permissions → Contents: **Read-only**. Срок — по желанию.
2. Repo → Settings → Secrets and variables → Actions → New repository secret `VNSHELF_UPDATE_TOKEN` с этим токеном.
3. Следующие сборки APK получат токен при компиляции, и проверка обновлений заработает сама.

Без секрета токен можно вставить вручную: «Настройки → Приложение → Токен GitHub для обновлений».
Учтите: токен, встроенный в APK, можно извлечь из файла, поэтому давайте ему только чтение и только этот репозиторий.
Когда репозиторий станет публичным, токен не нужен.
